# CHIDOSET — frontend preview

این نسخه پیش‌نمایش خصوصی فرانت‌اند مستقل چیدو است. هنوز روی دامنه `chidoset.ir` قرار نگرفته و به هیچ پایگاه‌داده، سرویس احراز هویت، سامانه پیامکی یا پرداخت واقعی متصل نیست.

## ساختار

- `dist/index.html`: صفحات معرفی، فروشگاه نمونه، داشبورد، ثبت‌نام و قوانین
- `dist/styles.css`: طراحی روشن، واکنش‌گرا و تایپوگرافی حداقل ۱۴ پیکسل
- `dist/app.js`: مسیریابی، رابط فروشگاه، داشبورد نمایشی و تعاملات
- `dist/scene.js`: مبلمان سه‌بعدی Three.js، حرکت وابسته به اسکرول، نمایشگر محصول و نمونه WebXR
- `dist/config.js`: **تنها نقطه پیکربندی وابسته به زیرساخت**؛ آدرس API، فایل‌ها، پیامک، پرداخت و کلیدهای امکانات آینده در اینجا تعریف می‌شوند
- `dist/vendor/`: فونت و کتابخانه‌های محلی برای کاهش وابستگی به CDN خارجی
- `dist/sofa-*.webp`: تصاویر سبک نمونه؛ در مرورگر فاقد WebGL جایگزین صحنه و تصویر محصولات می‌شوند

## استقرار

برای اجرای این فرانت‌اند، هر وب‌سرور استاتیک با HTTPS کافی است؛ هاست لینوکسی، استوریج ایرانی/وب‌سرور یا VPS هر سه قابل استفاده‌اند. ساختار فایل‌ها به Cloudflare یا شرکت خاصی قفل نیست. در محیط توسعه `sites-preview start ...` استفاده شده است.

در مرحله اتصال بک‌اند:

1. سرویس‌های ورود با شماره موبایل و OTP، صدور session در cookie با `HttpOnly`, `Secure`, `SameSite`, محدودیت دفعات OTP و دستگاه به‌یادسپرده‌شده ایجاد شوند. هر ورود نیاز به پیامک دوباره ندارد؛ جلسات معتبر باید روی سرور بررسی و قابل لغو باشند.
2. در `dist/config.js` endpointهای بومی یا داخلی تنظیم شوند. رمز، API key و token سرویس پیامکی نباید در JS مرورگر قرار گیرد.
3. محصولات، عکس‌ها، مدل‌های GLB و سفارش‌های آپلود در سرویس ذخیره‌سازی اشیای داخل ایران نگهداری شوند؛ کش طولانی برای فایل‌های نسخه‌دار، کش کوتاه برای اطلاعات قیمت و موجودی.
4. به‌روزرسانی نمونه `localStorage` در داشبورد با درخواست‌های احراز هویت‌شده به API، کنترل دسترسی فروشگاه و ذخیره‌سازی دائمی جایگزین شود.
5. اتصال کمپین‌های پیشنهادی/تلگرام صرفاً پس از تأیید صریح مالک فروشگاه انجام شود. پرداخت/فروش واقعی تا آماده‌شدن قراردادها و درگاه فعال نشود.
6. صفحات قوانین و حریم خصوصی قبل از انتشار عمومی از نظر حقوقی بررسی و اطلاعات واقعی شرکت و راه‌های تماس درج شوند.

**توجه:** دکمه‌ها و فرم‌های نمایشی نباید به عنوان حساب/خرید واقعی یا خدمات بالفعل معرفی شوند. از آنجا که WebXR برای واقعیت افزوده به مرورگر، HTTPS و سخت‌افزار سازگار نیاز دارد، تست عملی AR باید روی گوشی پشتیبانی‌شده انجام شود.
