# 0.14.0 — independent material groups per scene instance

The case-insensitive substring `fabric`, `body` or `detail` anywhere in a GLB material name defines its group. Prefixes, suffixes, Blender `.001` numbering and slot order do not matter. A name containing multiple group words is ambiguous and is left unchanged; assign each material one role. Several materials may share a role and change together. Meshes need UV coordinates and a standard/physical glTF material.

The app material sheet and company scene editor use three keyboard-accessible tabs: fabric, body/base, detail. Each available group offers image selection and reset to its original appearance. Fabric uses the existing three JPEG swatches; body includes three small procedural wood sample images encoded as JPEG; detail can use either sample collection. Each tab accepts a device image. Inputs (including PNG) are converted to JPEG at a maximum 512-pixel side, downsampled further if needed, with a maximum encoded source length of 90,000 characters. No PNG input copy is retained. Uploaded swatches are currently embedded in the scene/colorway JSON, not uploaded to a separate reusable texture catalog. This is bounded demo storage; a shared production material library would require a separate storage workflow.

Application targets a captured selected scene instance and the matching materials within its `imported-visual`. Each edited material has a private clone and original backup; shared image textures are immutable. Uploaded textures are instance-owned and released on replacement/deletion; preset images use a bounded role/preset cache. Per-role requests discard stale asynchronous results. Disposed objects cannot receive a late texture. AO and untouched groups remain intact. An absent or ambiguous role is never guessed on arbitrary uploaded models.

The three legacy demo sofas have one unnamed material each. Their existing fabric-only behavior is retained as a compatibility fallback. Body/detail require actual separate named materials assigned to faces in the source model. The old automatic sofa-fabric path now respects named groups, so a new multi-material sofa does not get fabric applied to body/detail.

Selections serialize under each item's `materialStyles`, survive reload/scene restore and cloning, and are included in live scene state. New official colorway JSON is version 2 and addresses item ID plus catalog index, so repeated instances of the same product retain separate choices. App and company editor read both new and legacy product-index colorways. No database schema, permission or backend function changes were made.

Validation: syntax checks and diff review only, per the user's request to perform application testing themselves. No local browser/unit/device tests were run. User verification should include two copies of one tagged product, independent edits in each group, rapid changes while loading, deletion before load completes, reset, and save/reopen. Physical-device AR behavior has not been retested for this feature.
